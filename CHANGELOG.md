# Changelog

All notable changes to Vultrino are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed (operators: read before upgrading)

- **An LLM-proxy request for a model the rate card does not price is refused (feir-ops#6).** `[llm_proxy] require_priced_model` defaults to `true`: `/llm` answers `403 model_unpriced` before any upstream call when the request's model (body `model`, or the id in a Gemini-style `models/<id>:` path) is not covered by the rate card at `[llm_proxy] rate_card_path`, the same JSON file leria reads. A model the card lacks used to be sent upstream and booked at $0 (leria rejects an unpriced token event), so a budget cap never tripped. **With no `rate_card_path` every model-bearing LLM call is now refused**: set the path, or set `require_priced_model = false` to opt out (posture reports it). A dated id (`claude-haiku-4-5-20251001`) is priced only by an explicit `model_ref_prefix` entry. `/api/v1/posture` reports `rate_card.sha256`, the fingerprint of the file.
- **Anthropic cache tokens are counted.** `cache_creation_input_tokens` and `cache_read_input_tokens` (and Bedrock's `cacheReadInputTokens` and `cacheWriteInputTokens`) are added to the input count, buffered and streamed: reads at the full input price (an over-count), writes at twice it (covers the provider's 1.25x and 2x). They used to be left out, under-counting spend.
- **A token meter event names the served model.** With a rate card configured the event is booked under the served model if the card prices it; the requested model stands in only for a dated form of it. Any other served model is booked under its own id, so leria counts it as unpriced instead of booking another model's price.
- **The gate follows the model the URL selects (review round 1).** For Gemini, Vertex AI, Bedrock and Azure OpenAI the model is taken from the upstream URL (`models/<id>`, `model/<id>`, `deployments/<name>` through the new `[llm_proxy.azure_deployments]` map); a body `model` that differs is refused, and a Bedrock call no longer needs a fake body model. The `allowed_models` check also applies to the URL's model.
- **Price modifiers the card cannot hold are refused (review round 1).** `speed` other than `standard`, `inference_geo` other than `global`, a priority `service_tier`, Bedrock latency-optimized or priority inference and server-side tools that bill per use now answer `403 modifier_unpriced`.
- **Extra-model calls and unlisted tools are refused (review round 2).** An `advisor_*` tool, `fallbacks` and `fallback_credit_token` answer `403 modifier_unpriced` (they run further models whose usage the token event does not book). The tool rule is now an allowlist: only function, custom, Anthropic client tools, `bash_*`, `text_editor_*`, `memory_*`, `computer_*`, `web_fetch_*`, `tool_search_*`, Gemini `functionDeclarations` and `urlContext`, and Bedrock `toolSpec` are accepted, so Vertex grounding and any server tool added later are refused. Gemini's camelCase `serviceTier` is checked like `service_tier`. A capability with `allowed_models` now works on Gemini, Vertex and Bedrock (the allowlist is applied to the model in the URL when the body names none); on Azure it matches the mapped model or the deployment name.
- **Unknown request features are refused (review round 4).** The price-modifier denylist is now an allowlist per provider protocol: a top-level request field, an `anthropic-beta` value (header or body) or a tool shape that the proxy does not know bills tokens alone answers `403 modifier_unpriced` before the upstream. That includes server-side compaction, `context_management`, `fallbacks`, `speed`, `inference_geo`, a service tier in any casing (even `standard`), `urlContext`, tool search and web fetch, and an untyped tool with a key beyond the plain function shape. Clients that send such a field must stop sending it. Every entry of `usage.iterations` is now counted in the booked tokens.
- **Audio and video modalities are refused until the card prices them.** A Gemini `inlineData` or `fileData` part is admitted only when its media type is an image, `application/pdf` or `text/*` (a missing type, such as a YouTube `fileUri`, is refused), wherever it sits in the body and whether `contents` and `parts` are arrays or single objects; a Gemini `responseModalities` must be a non-empty array of `TEXT`; an OpenAI chat, responses or Azure content part must be text or an image (`input_audio`, `file` and typeless parts are refused). A body nested deeper than 64 levels is refused. All answer `403 modifier_unpriced` before the upstream, buffered and streamed. Other nested options are still not inspected.
- **The rate card can only narrow after start, and parses as strictly as leria (review round 1).** A change to the card file is served as the intersection with the card read at start; unknown fields, a missing or repeated `rate_card_version` and a one-sided input or output price are now errors, as in leria. Posture gains `rate_card.file_sha256`.
- **Gemini thinking and tool-use tokens are counted (review round 1).** `thoughtsTokenCount` counts as output, `toolUsePromptTokenCount` as input, and a usage block without `candidatesTokenCount` still books its prompt tokens.

- **Outbound credential calls no longer follow an ambient proxy (VUL-29).** The HTTP plugin, the OAuth and HMAC paths, the averin and govder plane clients, the approval notifier, the outbox pusher and the request CLI ignore `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` (a test fails when a product client is built without `no_proxy`). An operator who needs a proxy sets `VULTRINO_UPSTREAM_PROXY` (an `http://` or `https://` proxy URL; an invalid value stops the process), and `VULTRINO_UPSTREAM_PROXY_CA_FILE` names a private CA for a TLS-inspecting proxy. Only `https://` targets use it. **A plain `http://` target is now refused by the HTTP plugin in every mode, and the averin and govder clients, the outbox pusher, the approval webhook and the request CLI refuse a plain `http://` endpoint that is not loopback or private** (at client build or config load, and by a connect-time resolver that returns only loopback or private addresses; compose and cluster service names keep working), with or without a proxy, because the plugin injects a credential and every target it can reach is public (loopback and private addresses were already refused; `internal_http` serves operator-pinned internal destinations over plain http). A deployment that sends a credential to a public `http://` URL must switch to `https://`. The proxy host must be an IP literal (a name would resolve through the target SSRF guard), and while it is set a target host this machine cannot resolve is refused at admission instead of being handed to the proxy. `GET /api/v1/posture` reports `egress.upstream_proxy_configured`. A deployment that relied on the ambient variables must switch to the new setting.
- **The inbound `[identity]` header must be signed by the edge (VUL-20).** The header is believed only with a `<header>-signature` value (`v1.<exp>.<HMAC-SHA-256>` under `VULTRINO_IDENTITY_SECRET`, bound to the request's bearer secret, valid at most 300 s). `vultrino web` refuses to start with `[identity]` and no key; an unsigned or badly signed document is ignored. See `docs/dev/CONFIGURATION.md`. No shipped sender sets this header today.
- **`url_match` footguns are refused on deny rules, in the config file and at stored load (VUL-32).** An exact URL or path with no query, and a pattern with a `{` or `}` other than `{credential}`, are refused on a deny rule (and on a prompt rule in a policy whose default is not deny) by the admin API, by config load, and when a stored policy is loaded: `vultrino web` then refuses to start and names the fix. New `vultrino policy check` lists such stored policies and `vultrino policy fix-url-patterns <id>` rewrites them (exact URL to `<url>*`, `{a,b}` expanded). A `UrlToken` secret holding `/`, `?`, `#`, a backslash, `%`, whitespace or a control character is refused at store and at use. The `internal_http` plugin now sends the canonical string policy judged.
- **A query appended to a URL never weakens a Deny or Prompt (VUL-32).** A Deny or Prompt `url_match` also matches the URL with trailing query parameters removed (flipped under `not`; Allow rules are not widened), and with one trailing `/` removed, so `/v1/*/delete` and `/admi[n]` match `?x=1` and `/delete/` too. A Deny or Prompt pattern that holds a `?` is refused (a parameter inserted before its own slipped past it); write the path and a trailing `*`. The widening is never weaker than the engine without it: a Prompt rule's widened match applies only when the unbroadened decision is Allow, so govder's exact-URL Prompt (an and of url and method, default deny) still prompts only on the exact URL and its query and trailing-slash variants stay denied. Trailing slashes, `;name=value` path parameters, repeated `/` and `%2F` are read as the plain path too. A Prompt rule's rate limit is charged only by its exact reading.
- **Approval-link capability tokens no longer reach request logs (VUL-39).** The request span records the method and path only, never the query string.

- **The admin API refuses risky `url_match` patterns on deny and prompt rules.** `POST` and `PUT /api/v1/policies` answer 400 (`invalid_policy`, naming the rule and the pattern) when a `deny` or `prompt` rule has, anywhere in its condition (inside `and`, `or` and `not` too), a pattern the canonical matcher warns about: `*` right after or inside a host (`https://api.example.com*`, `https://api.*`), `*` in the host (`https://*.example.com/*`, where an earlier `*` in a prefix pattern is literal and the rule matches no real host), a pattern whose meaning canonicalisation changes (dot segments, a fragment, a backslash, a `*` that cuts a percent escape), or one that is not a parseable URL or path. Such a rule can match less than it reads, so a deny or an approval gate would silently not apply. Allow rules are not refused (still a load-time warning), and neither are `[[policies]]` in the config file (warned at load). Policies already stored keep loading as written; their warning line now says the admin API refuses the pattern and that they are enforced as written until saved again.
- **A stored `RateLimit` policy with an allow or prompt default is refused on load.** Such a policy (only a vault written before the admin API validated it can hold one) used to load with a warning and let over-limit requests through at its default. Now `vultrino web` and `vultrino serve --mcp` do not start and print an error naming the policy and the fix; CLI commands that load policies fail the same way; a reload after an admin write returns an error and leaves the live set unchanged; the periodic refresh logs an ERROR and keeps the live set. Fix it offline with the new `vultrino policy deny-default <id>` (sets `default_action = "deny"`, keeps the rules), then start again. Other validation failures of a stored policy are still only warned.

- **Vault format v10: a write appends one record instead of rewriting the vault (one-way, backed up).** Every admin write used to re-serialize, re-encrypt and fsync the whole vault, and every dispatch took the exclusive vault lock and decrypted the whole vault for the kill fence. Now the vault file is a snapshot and each committed write is one small encrypted record appended to `<vault>.wal`: bytes written, records written and decrypt work per write no longer grow with the number of stored tokens, policies or kill marks (counted by `cargo run --release --example vault_cost`), the dispatch fence reads the vault under a shared lock and decrypts only the records appended since it last looked, and the log is folded into a fresh snapshot once it passes the larger of 256 KiB and the snapshot size (that one write still rewrites everything). The first start of this build copies a v9 or older vault to `<vault>.v9.bak` and migrates it; a v9 build refuses the migrated vault. Stop every vultrino process sharing the vault before upgrading. To roll back, stop all processes, delete the log (`credentials.wal` for `credentials.enc`), restore the backup (`credentials.v9.bak`) and start the v9 build; writes made after the migration are lost, and a log left beside the restored v9 file makes the open fail closed instead of replaying it. Back up a v10 vault by copying the vault file and `<vault>.wal` together. Not measured on native hardware.
- **A running process refuses when the vault file or its log is deleted under it.** Before, a process that had loaded the vault read a deleted vault file as a fresh empty vault (most easily right after a compaction, when the log is empty too), so a halted agent could turn clear, and a later write could recreate an empty vault. Now every dispatch fence read and every write of that process fails closed (`Unavailable`, so dispatch denies) while the file stays gone, and the same holds when the file vanishes during a reload or a compaction. The same refusal applies when the `.wal` is removed or shortened while the snapshot is unchanged. The refusal ends when a vault file reappears. A process started after the deletion finds no vault; offline `.wal` tail truncation is an accepted limitation (filesystem write access is outside the threat model). Back up the vault file and its `.wal` together.
- **Kill marks are garbage-collected.** The periodic vault GC drops a kill mark only when its kill policy is no longer stored, the mark is at least 24 hours old, and no approval that can still run was admitted before it. The kill epoch is never lowered. See LIMITATIONS for the bound on in-flight calls.

### Added

- **`vultrino vault backup <dir>` and `vultrino vault restore <dir> [--force]`.** Backup copies the vault snapshot, its `.wal`, the outbox and the averin stores together under the exclusive vault lock into a new empty directory, writes a manifest of SHA-256 sums, and checks the copy by re-reading and opening it. Restore verifies the manifest, every checksum and an open of the copy before touching the target, refuses a backup without the snapshot or the `.wal`, replaces an existing vault only with `--force` (the old files are moved aside as `*.pre-restore-<nanos>`), and leaves `<vault>.restore-pending` if interrupted, which stops the vault opening until the restore is re-run. Both refuse while a process holds the vault or the durable averin queue. (VUL-11)

### Fixed

- **A kill write is no longer starved by a stream of dispatches.** A writer now holds a sidecar `<vault>.gate` lock exclusively while it waits for the vault lock, and every fence read passes through that gate first, so reads that start after a waiting kill write queue behind it. (VUL-06)

- `url_match` globs (patterns without a trailing `*`) are matched part by part against a URL with a host: scheme, host, port, then path and query. A `*`, `?` or `[...]` in the scheme or host no longer matches `/`, `?`, `#`, `@` or the port, on Allow, Deny and Prompt rules alike. Before, `https://*.example.com/x` matched `https://evil.net/a.example.com/x`, and `*://api.example.com/x` (which logged no warning) matched `https://evil.net/?q=://api.example.com/x`, so an Allow rule could allow another host. Deny and Prompt globs match less as a result: a glob without a port (`https://*/admin`) no longer matches a non-default port, and a glob without a scheme matches a URL with a host only when it starts with `*`. Tested on listed patterns and a property test, not proved for every pattern.
- The load-time `url_match` warning no longer says warned patterns "will be refused in a future release". On an allow rule it says the pattern is only warned; on a deny or prompt rule it says the admin API refuses the pattern when a policy is written and that the stored policy is enforced as written.
- `cargo test --no-default-features --lib` passes: the WASM ABI install test now runs only with `wasm-plugins`, and a twin test pins that a build without the feature refuses every WASM install before anything is copied. CI runs this command in the `rust` job.

### Changed

- For `UrlToken` credentials the `http` plugin now sends the judged canonical URL (including the merged `query` map) with the secret in place of the literal `{credential}` placeholder. Before, it sent the raw URL with the token substituted and let the client append the `query` map afterwards, so the bytes sent could differ from the judged string in spelling (escapes, hex case, trailing host dot, query order). A request is now refused when text other than a literal `{credential}` in the URL canonicalises to a spelling of the placeholder (for example `%7Bcredential%7D`, the half-encoded `%7Bcredential}`, or `%7Bcr%65dential%7D`, whose escaped letter canonicalisation decodes); before, such text was sent literally. This is tested on a list of spellings, not proved for every URL.
- A policy that fails validation when it is loaded from the vault (for example a nested `SpendCap` saved before that was refused) now logs a WARNING once per process. It is still enforced as written, except a `RateLimit` policy with a non-deny default, which is refused on load (see above).
- The scheme-prefix patterns `http*` and `https*` no longer log the star-in-host warning. Other scheme-less prefixes (`internal*`, `api*`) still do: they match no canonical `http(s)` URL.
- Reported with the permit-kernel change below: an approval whose stored action has no `.` now fails closed at resume with a binding mismatch, because the action is dispatched as `http.<action>`. Approvals opened by `prepare_execution` always store a dotted action.
- argon2 0.5.3 to 0.6.0. In the tested cases the vault master key is unchanged: tests/argon2_kat.rs opens vault files and AES-GCM blobs written by 0.5.3 and checks that new vaults persist the same cost parameters. These are fixed cases, not every password, salt or cost setting. One input now behaves differently: a salt longer than 48 bytes, which 0.5.3 rejected, is accepted; vultrino only creates 16-byte salts. Replaces Dependabot PR #32.

### Added

- Open-source release hygiene: `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, Dependabot, release/GHCR workflow, and committed `Cargo.lock`.
- Stage-1 formal verification artefacts under `formal/` (Lean critical-boundary model, Kani harnesses, refinement gate), with CI jobs on `main`.
- Declared human-floor / ambiguous shared-canonical actions require a committed Averin use seal before dispatch; Observe cannot weaken that floor. Unknown `[averin]` modes refuse at config load.

### Changed

- The execution permit is minted from the policy engine's evaluation of the request on the direct path, and from the approval grant plus the policy evaluation made at resume on the approved path. `authorize` recomputes the binding from the payload it is about to dispatch (plugin and action, credential alias, params digest, request or approval id, epoch, tenant, principal) instead of receiving a copy, and refuses a mismatch. Valid requests behave as before. A Deny that observe mode lets run is recorded on the permit as its own kind. The URL and method these evaluations judge are now taken from the params inside the policy engine (same `policy_url` function).
- `url_match` now compares a canonical URL (case, default port, dot segments, trailing host dot, percent-encoding) and the caller's `query` map is part of the judged URL. The `http` plugin sends the canonical string: unreserved percent escapes are decoded and hex is upper-cased, so an upstream that signs the literal encoded path can see different bytes. URLs with userinfo or that cannot be canonicalised are refused. Risky patterns log a warning at load and are refused on deny and prompt rules when a policy is written through the admin API (see above).
- Policies that contain a `RateLimit` condition (at any depth) must now set `default_action = "deny"`, like `SpendCap`. Config load and the admin API refuse other defaults, because when no other rule matches, an exhausted Allow-`RateLimit` rule falls through to the policy default, which would allow the request under an allow default (or ask for approval under a prompt default). Default deny does not stop another matching allow rule from allowing an over-limit request. A stored policy with that shape is refused on load (see above).
- Docs: the rate-limit examples in the policies guide now put `rate_limit` inside the rule it limits. The earlier examples used a separate allow rule whose only condition was `rate_limit`, which allowed any URL on the credential until the limit was spent. The guide's evaluation order section now describes the kill check and the deny, prompt, allow tiers instead of "first matching rule in written order".
- Policy precedence is now decided by a lazy tier scan and a verdict-to-decision mapping in `src/policy/precedence.rs`; behaviour is unchanged. The former unreachable tail that returned Allow now denies.
- Repository identity targets the `FeirAI` GitHub organization (`https://github.com/FeirAI/vultrino`).
- Documentation install paths and clone URLs updated for the org cut; TLS requirements clarify rustls (no OpenSSL toolchain dependency).
- Bump Rust toolchain pin to **1.95.0** and wasmtime/wasmtime-wasi to **48.0.4** (RUSTSEC-2026-0314/0315/0316/0321/0322/0323/0324/0325/0326/0327; earlier: RUSTSEC-2026-0188, RUSTSEC-2026-0222).
- Default feature `wasm-plugins`; Kani CI / `formal/run-kani.sh` use `--no-default-features` so proofs stay off wasmtime’s rustc-1.95 MSRV (Kani 0.67 ships rustc 1.93).
- Dependency refreshes (API-adapted where needed): `aes-gcm` 0.11, `rand` 0.10 (`OsRng` → `SysRng`), `sha2` 0.11, `hmac` 0.13 (`KeyInit`), `sha3` 0.12, `k256` 0.14 (`to_sec1_point`), `bcrypt` 0.19.3, `base64` 0.23, `toml` 0.9, `tower-http` 0.7; GitHub Actions checkout/buildx/metadata/build-push/gh-release majors.
- `docs/dev/` refreshed for the org cut, formal-gate bounds (LIMITATIONS), and SysRng/crypto crate notes.
